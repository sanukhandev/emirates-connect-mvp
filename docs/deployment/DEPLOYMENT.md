# Deployment Strategy

## Environments
`dev` -> `staging` -> `production`. Use separate DBs, storage buckets, credentials, API URLs and signing secrets.

## Parent orchestration
Parent workflows pin exact submodule SHAs, validate contracts/pointers, then invoke/deploy each component. Replace placeholder commands in supplied workflow templates with the chosen hosting provider.

## Backend
Build immutable artifact/container, install Composer production dependencies, run tests before deployment, run migrations using a controlled release step, restart workers, health check `/api/v1/health`, support rollback. Destructive migrations require expand/migrate/contract sequencing.

## Angular + Tailwind
- Install locked dependencies.
- Run formatting/lint/unit tests.
- Compile the Angular production build; Tailwind output must be generated by the normal application build pipeline.
- Ensure Ubuntu/font assets use the agreed production delivery mechanism.
- Build with environment-specific API origin.
- Publish immutable static assets and CDN-cache fingerprinted assets.
- No secrets in the browser bundle.
- Add bundle-size budgets and fail production CI on unexpected regressions.

## Flutter
CI runs format/analyze/test/build. Store releases should use signed release artifacts and protected signing credentials. Mobile release cadence is independent from web/API, so APIs must remain backward compatible across supported app versions.

## Release validation
Before promotion, verify API health, authentication, post/feed flows, business pages, comments/replies, verification state and media/reel playback. Web smoke checks must also verify that Tailwind/Ubuntu assets load and the primary brand tokens render correctly.
